# 模块呈现与整合审查标准（MODULE REVIEW STANDARD）

> 本文件汇集六爻「开刀」过程中确立的全部原则与查出的全部问题型态，
> 作为**未来每一个模块（八字·六爻·紫微·奇门·玄空·择日·阳宅）上线前的强制审查清单**。
> 任一模块未逐项通过，不得视为「完成」。
>
> 最高纲领：**一个系统所算的每一子模块，都必须组合进对所问/命主的最终解释。
> 算而不用、沦为孤立面板者，即为缺陷。几个子模块拼合，应成「一个视角」的解读。**

## ★ 深度架构「六件套」—— 每个功能的核心审核单元

> 凡一功能（六爻/八字/紫微/奇门/玄空/择日/阳宅）欲称「完整」，必备此六件，缺一不可。
> 六爻为完整范本；后续每模块逐件补齐，并以此六件回头审核所有功能。

## A. 功能完整性（Completeness）—— 后端算了，前端有没有呈现？

- [ ] **逐字段核对**：对照该模块每个 API 端点的**全部返回字段**，确认前端是否真正渲染。
      方法：TestClient 取真实返回 → 逐字段 grep 前端引用。
- [ ] **无静默隐藏**：警惕「字段存在但渲染条件写错」导致整块不显示。
      - 案例：`fu_shen` 后端返回**单 dict**，前端却 `data.fu_shen.length>0 && .map()`（dict 无 length）→ 有伏神反而永不显示。
      - 案例：`SpecialPatternsCard` 守卫 `sp.total`、`geju_evaluation` 守卫 `verdict`——守卫字段不存在则整卡消失。
- [ ] **无字段名不一致**：同一份数据在不同组件用了不同字段名 → 一处丢失。
      - 案例：神煞位置后端是 `s.pillar`，一处组件读 `s.position`（不存在）→ 永不显示位置。
- [ ] **富字段不可只喂 AI**：注入 AI prompt 的古籍/断语，必须**同时呈现给用户**。
      - 案例：八字调候/滴天髓/子平真诠原文，原仅入 prompt、用户看不到 → 须建「传统断语」层surfaced。
- [ ] **无死代码功能**：界面上看似实现、实则数据永不到达的块（如八字 `true_solar_time`、六爻 `hex_type==六合` 永假分支）须修复或移除。

## B. 三层呈现范式（Three-Layer Presentation）—— 服务最终问题

每个有「问题/主体」的界面，必须具备且按此顺序：

1. [ ] **综合总论（散文·置顶）**：把各结构化结果**编织成连贯叙述**，扣住所问/命主，
       而非分类词条罗列。（八字`命局总论`、六爻`断卦总论`为范本。）
2. [ ] **传统断语（古籍·有出处）**：完整呈现古籍原文断语，标明出处（《增删卜易》《子平真诠》等）。
3. [ ] **AI 分析解读**：`AiInterpretPanel`，且**喂入上层综合**（标注"在此基础上深化"），
       使 AI 承接综合、扣住提问，而非从零堆砌。

## C. 子模块整合（Integration）—— 最根本逻辑

- [ ] **互助而非孤立**：子模块的核心评估须**相互回馈**，不得各算各的。
      - 案例：六爻用神 force 原仅由月日算出，`回头生克`只是标签不入力、`三合合起`完全不计
        → 建`用神力量综合评估`，把 旺衰×动变×三合×空破墓×四位 汇于用神一身。
- [ ] **推理链可见**：把「各子模块如何汇入、利害几分、合成何结论」**显式呈现**
      （每因子标注来源模块 + 利/害/中 + 权重）。
- [ ] **尽其用·无孤儿**：用 coverage 核查——**每一分析型子模块都须被至少一个**
      综合层 / 视角 / 传统断语层消费。孤儿（算了没用进解释）即缺陷。
      - 六爻曾查出 11/18 子模块为孤儿（topic_verdict、chi_shi、gua_shen、deep_relations、
        dong_jing、shi_shen、world_summary…）→ 建`多视角整合解读`六视角悉数纳入。
- [ ] **多视角解读**：数子模块拼为一「视角」，各成专业观照（用神得失·人我向背·
      动变趋势·格局聚散·生克情态·时机应期），合参方见全貌。

## D. 跨模块一致性（Consistency）—— 确定性检测 + AI 审定

- [ ] **确定性审核引擎**：据已知矛盾型态核查跨模块结论是否自洽，可测试、可复现。
      须查的矛盾型态（六爻已实现，他模块类比）：
      - 用神状态 vs 应期：综合断言不墓、应期却按入墓推算（**已实检出真矛盾**）。
      - 用神两现取舍未明（持世/临应/独发）。
      - 吉凶极性跨模块分歧（综合断 vs 总览 vs 专断）。
      - 综合力量 vs 结论张力（无力却言吉 / 大有力却言凶）。
      - 子模块自身错算（如`dong_jing_analysis`报"全静"而实有 3 动 → moving_count 失准）。
- [ ] **AI 审定层有界**：AI 只**复核、不重断**，明标"AI 辅助·不作准"，**绝不覆盖**确定性结论。
- [ ] **分层呈现**：确定性发现（按矛盾/注意/提示着色）在上，AI 审定意见在下并明确区分。

## E. 视觉与排版（Typography & Layout）

- [ ] **字号统一**：全部 `fontSize` 收敛到令牌阶梯
      `--text-2xs/xs/sm/base/md/lg/xl/2xl/display`，禁止散落的硬编码 rem（曾达 28 种近似值）。
- [ ] **无单双引号混用**：`fontSize:'var(...)'` 统一单引号。
- [ ] **无内容重叠**：固定宽度文本容器、`whiteSpace:nowrap`、`position:absolute`、
      magic `paddingLeft` 对齐——逐一检查是否会在长内容下重叠/截断。
- [ ] **保留刻意取舍**：紫微十二宫格 0.45/0.52rem 微型字为防撑破布局而保留——专业取舍可豁免。

## F. 工程纪律（Engineering Discipline）

- [ ] **合成优于查表**：synthesis engine 优于 flat lookup（项目既定原则）。
- [ ] **不臆造古籍**：缺失数据宁可不写。六冲/六合卦据纳甲地支**严格计算**，不背诵可疑表。
- [ ] **复用既有引擎**：新子模块复用已有 五行/旺衰/游年 等，不另起平行逻辑。
- [ ] **每里程碑必验**：pytest 全过 + 改动 JSX 转译 + hooks 全过，方可打包。
- [ ] **差异测试**：变输入确认输出随之变，排除硬编码样本。
